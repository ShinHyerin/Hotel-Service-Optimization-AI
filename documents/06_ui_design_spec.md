# 🎨 06. 화면 설계서 (UI/UX Design Specification)

본 문서는 Flask 기반 호텔 예약 취소 확률 예측 시스템의 주요 화면 구성 및 프론트엔드-백엔드 간의 인터랙션 로직을 정의한 화면 설계서입니다. **Jinja2 컴포넌트 분리 구조**와 **Fetch API 기반 비동기 처리**를 핵심 인터랙션 지표로 삼고 있습니다.

---

## 🏠 1. 메인 페이지 (index.html)

메인 대시보드 및 서비스 소개 공간으로, 사용자 흐름의 시작점입니다.

### 📌 UI Component Description
| 번호 | 컴포넌트 명칭 | 상세 기능 및 라우팅 명세 |
| :---: | :--- | :--- |
| **1** | **내비게이션 바** | 페이지 스크롤 및 위치 변화와 관계없이 항상 화면 상단에 고정 노출 (Fixed Layout). |
| **2** | **로고 (Logo)** | 상단 좌측 배치. 버튼 클릭 시 최상위 메인 페이지(`/`)로 즉시 이동. |
| **3** | **예약 정보 검색** | 버튼 클릭 시 고객 예약 내역 검색 및 취소 관리 페이지(`search.html`)로 라우팅. |
| **4** | **Predict Now** | 메인 배너 내 위치. 버튼 클릭 시 AI 취소 확률 예측 페이지(`predict.html`)로 즉시 이동. |
| **5** | **좌측 고정 내비게이션 바** | 사이드 퀵 메뉴. 마우스 호버(Hover) 시 글자가 나타나며, 클릭 시 해당 섹션으로 부드럽게 이동. |
| **6** | **Home (메인 캐러셀)** | 세 페이지 분량의 핵심 비주얼 배너가 자동으로 슬라이드되며 서비스 아이덴티티 노출. |
| **4 (하)** | **Why Prediction Matters** | Section 2 영역. AI 기반 예약 취소 예측 모델이 필요한 비즈니스적 이유를 3가지 관점으로 분류하여 설명. |
| **5 (하)** | **How It Works** | Section 3 영역. 취소율 예측, 그래프 확인, 예약 정보 검색을 통한 본인 내역 확인 프로세스를 Step별 일러스트와 함께 안내. |
| **6 (하)** | **Key Features** | Section 4 영역. 딥러닝/머신러닝 모델링에 사용된 핵심 피처(Feature)들이 실제 예측에 기여하는 메커니즘 소개. |

### 🔍 Technical Check Point
* **풀페이지 스크롤 (Full-Page Scroll):** 마우스 휠 이벤트를 정밀 제어하여 일반적인 연속 스크롤이 아닌, 섹션(Section) 단위로 화면이 딱딱 맞아떨어지며 부드럽게 넘어가는 모던 UI 스크립트 적용.
* **컴포넌트 분리 구조:** Flask의 내장 템플릿 엔진인 **Jinja2 (`{% include %}`)**를 적극 활용하여 헤더, 푸터, 섹션별 HTML 및 CSS 단위를 모듈화. 코드 가독성과 유지보수성을 극대화.

## 🔮 2. 예측 페이지 (predict.html)

사용자가 조건을 입력하여 실시간으로 AI의 취소 확률 추론 결과를 확인하는 핵심 폼(Form) 화면입니다.

### 📌 UI Component Description
| 번호 | 컴포넌트 명칭 | 상세 기능 및 라우팅 명세 |
| :---: | :--- | :--- |
| **1** | **실시간 듀얼 차트 (`Chart.js`)** | 휴양형 호텔(Resort Hotel)과 도심형 호텔(City Hotel)의 취소 확률을 도넛 그래프 레이아웃으로 병렬 시각화. 입력 폼 변경에 따라 실시간 동적 차트 업데이트 애니메이션 렌더링. |
| **2** | **인공지능 실시간 분석 리포트** | 백엔드 모델이 계산한 확률 데이터를 기반으로 현재 리스크 상태를 **[HIGH RISK / STABLE STATUS]** 등급으로 자동 판별하고, 텍스트 스토리텔링 방식의 맞춤형 인사이트 리포트를 실시간 출력. |
| **3** | **예약 및 개인정보 입력 폼** | 고객 이름, 연락처, 예약일, 객실 요금, 추가 요청 사항(Lead Time 자동 계산용) 등의 변수를 수집하는 영역.<br>• `[입력 초기화]` 클릭 시: 모든 Form 데이터 및 Chart.js 객체 리셋.<br>• `[예약하기]` 클릭 시: 최종 확정 데이터를 Oracle DB와 연동하여 `INSERT` 비즈니스 로직 수행. |

### 🔍 Technical Check Point
* **비동기 실시간 예측 트리거 (Refresh-less Trigger):** 사용자가 폼 내부의 `input`, `select`, `textarea` 값을 변경할 때마다 페이지 새로고침 없이 **JavaScript Change Event**가 발생하여 백엔드 API(`/api/predict`, POST)와 실시간 통신 후 차트 데이터를 즉각 리로딩.
* **파싱 및 유효성 검증 예외 처리 (Validation):** 예약 날짜(Arrival Date)와 현재 시점 간의 차이를 계산해 선행 기간(`lead_time`) 변수를 자동 연산. 추가 요청 사항의 문자열 길이에 따라 가중치 가변 처리. 전화번호 입력란은 정규식을 활용하여 숫자 이외의 문자 입력을 원천 차단.

## 🔍 3. 예약 정보 검색 및 관리 페이지 (search.html)

고객이 자신의 기존 예약 정보를 조회하고, 동적으로 예약을 취소하여 모델 가중치 갱신 트리거를 발생시키는 통합 관리 화면입니다.

### 📌 UI Component Description - [상단: 검색 및 대시보드 영역]
| 번호 | 컴포넌트 명칭 | 상세 기능 및 라우팅 명세 |
| :---: | :--- | :--- |
| **1** | **실시간 누적 취소율 대시보드** | 페이지 로드(DOM Ready) 시 즉시 백엔드 통계 API(`/api/chart-data`, GET)를 호출하여, Oracle DB에 적재된 휴양형 및 도심형 호텔의 실제 누적 취소 현황 지표를 수집 후 도넛 그래프로 시각화. |
| **2** | **예약 내역 조회 정보 입력 폼** | 고객 이름, 생년월일, 전화번호를 입력받아 DB 세션 조회를 준비하는 영역. 생년월일 선택 시 윤년 계산 알고리즘 및 월별 마지막 일수(`lastDay`) 파싱 로직이 자바스크립트로 자동 구동되어 잘못된 날짜 선택 필터링. |

#### 🔍 상단 영역 Technical Check Point
* **사용자 친화적 예외 처리:** 조회 폼 입력 누락 시 커스텀 벨리데이션 알림창(Modal)을 띄움. 데이터베이스 내부 조회 결과 일치하는 정보가 없을 경우, 프론트엔드 단에서 *"일치하는 예약 내역이 없습니다."* 경고 레이어를 노출하고 하단 결과 창을 `display: none`으로 즉시 은닉 처리하여 UI 붕괴 방지.

### 📌 UI Component Description - [하단: 조회 결과 리스트 영역]
| 번호 | 컴포넌트 명칭 | 상세 기능 및 라우팅 명세 |
| :---: | :--- | :--- |
| **1** | **비동기 예약 내역 리스트창** | 상단 폼에서 `[예약정보조회]` 버튼 클릭 시 백엔드 엔드포인트(`/search_booking`)로 비동기 요청을 전송. 수신된 고객의 매칭 데이터를 하단 영역에 세련된 **카드 레이아웃(Card Layout)** 구조로 동적 렌더링. |
| **2** | **예약 취소 트리거 버튼** | 조회된 개별 예약 정보 카드 내 우측 상단에 활성화되는 `[예약취소]` 컨텍스트 버튼. 클릭 시 고유 UUID/ID 기반의 백엔드 취소 API(`/cancel_booking/<id>`, POST)를 즉각 호출하여 DB 상태를 동기화. |

#### 🔍 하단 영역 Technical Check Point
* **비동기 데이터 갱신 파이프라인 (Refresh-less Update):** 사용자가 `[예약취소]`를 최종 승인하면 화면 전체를 새로고침(F5)하지 않고, 자바스크립트가 백라운드에서 기존 검색 버튼 클릭 이벤트(`btnSearch.click()`)를 내부적으로 재트리거함. 이를 통해 상단의 실시간 전체 취소 통계 대시보드 차트와 하단의 본인 예약 리스트가 실시간 동기화되어 실시간 피드백 루프 완성.
